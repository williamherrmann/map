What's New
v116 Realtime debug logging for share sync
Sharing/unsharing a pin or shape still requires a refresh to show up for the other person on some setups — that points to a Supabase configuration step, not the app code, so this release adds detailed console logging around the item_shares realtime channel: whether it subscribes successfully, and every insert/update/delete event it receives. Open the browser console after sharing or unsharing something to see exactly what's happening.
v115 Fixed unshare flash + reply delete sync
Pins/shapes shared with you were briefly flashing on screen for a moment on page load even after being unshared — the map was rendering every row the instant it came back from Supabase, then removing the unshared ones only after a slower follow-up check finished. Reordered it so nothing renders until that check is done, so a revoked share never appears at all. Also fixed deleted feed replies not disappearing for other people without a manual refresh — the realtime delete event doesn't always include which post it belonged to, so a fallback now refreshes every reply list currently on screen when that happens.
v114 Reply loading fix + realtime debug logging
Replies now always show a composer even if the list of existing replies fails to load, instead of silently blocking you from replying. If posts, replies, or shares still aren't appearing live without a manual refresh, check the browser console — realtime subscriptions now log a warning there naming exactly which Supabase tables need Realtime replication turned on (Database → Replication in the Supabase dashboard).
v113 Instant unshare, muni highlight fix, feed replies
Unshared pins/shapes now disappear instantly for whoever they were shared with — no more "Shared by @unknown" ghost pins, and both sides sync live over realtime the moment a share is added or removed. Added a "Remove" option so the person a pin/shape was shared with can drop their own access without waiting on the owner. Fixed a municipality staying highlighted and filled after closing its popup — it now reverts to whatever the Layers panel currently has selected. Added replies to feed posts, with their own up/down votes and a show/hide toggle per post (no replies-to-replies). The feed now updates live too — new posts, replies, and votes show up immediately while it's open, no refresh needed.
v112 Share Today's Schedule
Tap a friend in the Friends tab to open their settings and flip on "Share Today's Schedule" — instead of sharing shapes one at a time, this keeps whichever shapes you have scheduled_at set to today automatically shared with that friend, view-only. It stays in sync: saving a shape, unscheduling one, or opening the app re-checks what's "today" and adds/removes shares to match. Turning it off removes those auto-shared shapes immediately; it never touches anything shared manually from a pin/shape's own Share button. Friends with it turned on show a small calendar icon next to their name in the Friends list.
v111 Fixed 403 error saving pins/shapes
Saving an existing pin or shape (including just updating Scheduled Visit) could fail with a 403. The save code intentionally stopped sending user_id on updates so an edit-access friend saving a shared item couldn't accidentally steal ownership — but under RLS, Supabase's upsert() checks the INSERT policy against that same payload first, and with no user_id present that check always fails. Switched pin/shape saves to a plain UPDATE for existing items and a plain INSERT for new ones, which only ever evaluates the correct policy and avoids this entirely.
v109 Fixed Share sheet peeking on desktop
The Share picker's desktop floating-card layout was using the same percentage-based slide-away transform as the full-width mobile sheet. For a short card anchored by fixed bottom/right offsets, that math doesn't always travel far enough to fully clear the viewport, so it could stay visibly peeking in the bottom-right corner even when "closed." Switched it to a fade + scale hide with pointer-events disabled while closed, which is reliably fully hidden regardless of content height.
v108 Friends + pin/shape sharing
Added Friends: search other users by username, send/accept/decline friend requests from a new Requests tab, and remove friends. Added a Share button on pins and shapes so owners can share individual items with friends as View-only or Can-edit, see who a pin/shape is shared with from its info sheet, and remove access with one tap. Shared pins show a small link badge on the map and shared shapes render with a dashed outline; opening one shows who shared it and your permission level.
v107 Settings redesigned as a sheet
Settings now opens as the same bottom sheet used everywhere else in the app (Customize Avatar, Builders, Pin/Shape details) instead of a separate full-screen page — same drag handle, same close button, same slide animation, same shared backdrop.
Fixed a layering bug where the Customize Avatar sheet could render invisibly behind Settings when opened from Edit Profile.
v106 Cache-busting for script files

Settings page navigation now logs a clear error to the console if a page fails to switch, to make this easier to diagnose in the future.
